# 界面审计实验（C3）

> 建立于 2026-10-07。跑之前写下方案和预测，跑完不改这两节。
> 代码：prototype 分支 `genui-audit`，`exp/audit.ts`、`exp/audit-report.ts`。

## 问的问题

让模型为用户生成当前这一步的界面（一组按钮和表单）时，界面上会出现多少当前用不了的控件？

## 做法

- 24 个任务的起始状态和目标，与六条件实验相同。
- 2026-10-21：任务集换为 v3（`25057cd`，修正 T2 判定：意图前提、同义动作、路线不经承诺动作）。19 题与旧集相同，5 题新增。此时审计尚未用模型跑过，预测未改。
- 2026-10-21：27b 试跑 3 题 × 5 条件后改了 system prompt。原文 "Show only controls the user can actually use on this site right now, and only those that help with the goal" 使模型每个界面只给 1 个控件，界面退化为"推荐下一步动作"，与 agent 实验测同一件事。改为"展示与目标相关、用户此刻可能想用的控件，不只是下一步"，"只展示此刻能用的控件"这条要求保留。各条件同一改动。试跑日志在 `exp/audit-logs/smoke/`，不计入结果。预测未改。
- 每个（任务 × 条件 × 模型）只调用一次模型，不执行动作，t=0。
- 模型输出 JSON：一段给用户的话，加一组控件。每个控件包括引用的操作、按钮文字、字段（每个字段标为 固定 / 预填 / 问用户）。

| 条件 | 模型拿到什么 | 控件怎么引用操作 |
| --- | --- | --- |
| P | 原始 HTML | 自己写 method + url + 字段 |
| J | 页面文字 + 全部 21 个操作 | 操作名 |
| J+ | J + 前置条件说明 | 操作名 |
| X+ | 页面文字 + MCP server 按状态过滤后的工具表 | 工具名 |
| H | 页面文字 + 页面上的控件列表 | 下标；字段由渲染器生成，模型不碰 |

X（静态 MCP）不单独设：生成界面时不发生工具调用，X 拿到的信息和 J+ 相同。

## 检查项（每个控件）

| 项 | 判定 |
| --- | --- |
| 死控件 | 引用的操作不在当前状态的合法集合里 |
| 不存在的操作 | 引用的操作在站点里没有 |
| 按下去不成功 | 操作合法，但带着界面给定的值提交被拒（实际发请求，之后恢复状态） |
| 编造字段 | 字段不是该操作声明的参数 |
| 漏掉必填字段 | 该操作声明的参数，界面上既没给值也没问 |
| 多问 | 让用户填一个当前状态已经确定的值（以 H 中同一操作的控件是否已带值为准） |
| 编造个人信息 | name / phone / card / reason 被填了目标和页面里都没有的值 |

每个界面：是否给出了能推进目标的控件（T1：可直接完成目标的操作；T2：通往目标的第一步；T3：不应出现完成目标的控件）。

H 下前六项结构上为 0，不是测量结果。

## 预测（跑之前写）

- J / J+：死控件明显大于 0，低于目录扫描的 87.9%。J+ 低于 J。
- X+：死控件接近 0；漏字段、多问比 H 多。
- P：死控件低，但会出现不存在的操作或写错路径，小模型更多。
- 目标覆盖率各条件差别不大。
- 如果 J / J+ 的死控件也接近 0：界面侧论点变弱，照实写。

## 模型

qwen3.5 2b / 4b / 9b（本地 Ollama），qwen3.8-27b（托管）。

2026-10-21：最终只用 **9b 和 27b**。Ollama 默认上下文 4096，审计要模型设计整个界面，qwen3.5 思考很长，被截断后输出为空（失败的调用 token 总数都正好 8192 = 两次尝试 × 4096）。9b 有 3 个（都在 H：T2-02、T2-05、T2-06），4b 87 / 120，2b 前 11 个全部。改成 `OLLAMA_CONTEXT_LENGTH=16384` 只重跑 9b 的这 3 个（t=0 下，4096 内写完的调用换大上下文结果不变，所以只补被截断的等价于全部重跑）。4b / 2b 不再做，日志留在 `exp/audit-logs/archive-ctx4096/`。
