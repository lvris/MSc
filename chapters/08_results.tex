\subsection{C2: filtering by state removes most errors; choosing from the page removes all}\label{sec:eval:results:c2}

\todo{\textbf{(我)} 论点句：按状态过滤工具表能消掉大部分错误；但只有让 agent 从页面控件里挑（返回下标），才是结构上保证为 0。}

\todo{事实要点（同一张表 \ref{tab:eval:invalid} 的 X+ / H 列）：
(1) X $\rightarrow$ X+ 只差状态过滤：9b 65.9 $\rightarrow$ 0，2b 71.1 $\rightarrow$ 3.5。这是协议之外、状态依赖本身的作用。
(2) X+ 下 2b 的 4 次越界\emph{全是} stale tool：调用了前几步见过、状态变了以后已经撤下的工具。X+ 的 agent 生成的是工具名（字符串），可以是任何字符串；H 的 agent 返回下标，越界的下标根本表达不出来。过滤决定"给了什么"，选择方式决定"能说出什么"。
(3) H 的 0 不随模型能力变；X+ 的 0 随能力变（27b / 9b / 4b 为 0，2b 不为 0）。
(4) random 只能从给定集合里挑：H 下成功率 37.5\%，J 下 16.7\%（表 \ref{tab:eval:success}）。这部分成功来自约束，不来自模型。
(5) P（读原始页面自己构造请求）：27b、4b 为 0，2b 48.9\%。大模型读页面也能不出错，所以不主张"H 比 P 更准"，只主张 H 是结构性的。}
